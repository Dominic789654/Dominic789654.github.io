用 Decision API 承载 DiffAdapt

研究札记 · 草稿 · 刘翔 · 2026 年 10 月

测试时算力（思维链、长思考轨迹、搜索）已成为 LLM 推理的一等杠杆（Wei et al., 2022；Snell et al., 2024；Weng, 2025）。更多思考并不总更好：模型会在简单题上过度思考、烧掉并不改答案的 token，并在共享 serving 下制造长尾（Sui et al., 2025；Li et al., 2025）。

两条近期线索指向更干净的控制环路。DiffAdapt 用轻量探针读 prefill 隐状态，为每题选择 Easy / Normal / Hard 推理策略（Liu et al., 2025）。Decision 接口——TypeSafe 的 System One / Jev（TypeSafe；JevServe 博客）与 SGLang 的 /v1/decisions（及 /v1/systemone）（SGLang 文档）——把带类型的问题变成标签概率，不生成任何文本。本文勾勒二者如何拼合。不宣称新实验；以下仅为开放方向。

DiffAdapt 已给出的结论

在多款推理模型上，轨迹 token 熵对题目难度呈 U 形：简单题高熵却高正确率（过度思考）、中等难度低熵、难题高熵（约自简单到中等下降 22–25%）。DiffAdapt 用最后一层 prefill 隐状态上的小型 MLP，映射到三套固定策略（prompt + temperature + max tokens）——不微调基座 LLM。五模型、八基准上准确率持平或提升，token 最多减少约 22.4%（Liu et al., 2025；ICLR 2026）。

论文自述局限：路由仅 prefill；策略标签来自代理采样协议；激进 Easy 预算偶发截断（其 LLM-as-judge 检查中约 2%）。

Decision API 改变了什么

据 SGLang decision-models 文档（2026-10 核对）：

  • POST /v1/decisions 在答案标签位置用 next-token 分数回答 choice / score / yes_no；completion tokens = 0；返回 probabilities 与 label_mass（所给标签在全词表上的质量）。思考默认关闭。
  • POST /v1/systemone 兼容 System One 请求形状（noul / choice / score）；普通 chat 模型走同一打分路径，决策专用 checkpoint（如 Jev 类）走各自校准路径。
  • 文档明确：返回概率 不是 校准后的正确率——阈值需用标注数据验证。

TypeSafe：System One 返回类型化决策（Choice / Score / Noul）而非自由文本；Jev 为其旗舰。JevServe 报告 Jev 在内容判断上更强、在预测「其他系统会做什么」上较弱；其 输出长度 预测在 H200 回放中可将 vLLM SLO 达成率自 75% → 99%，P90 TTFT 自 8.3 s → 0.17 s（数字来自该文，本文未复现）。

引擎不对称：SGLang 已文档化 /v1/decisions；可移植的 DiffAdapt×decision 栈目前偏 SGLang-native，除非移植该接口。

缺失的中间件

DiffAdapt 决定 该多认真想。Decision API 在准入时（原则上也可在生成中段经 /v1/score）决定 关于请求的结构化事实。Serving 对优先级、max tokens、投机深度、KV 预留仍多靠固定规则——尽管难度未建模时推理负载易长尾（Li et al., 2025）。

假设：把 Easy/Normal/Hard（外加「是否 think」、期望长度）打成一次 decision 调用，结果喂给调度器——即 DiffAdapt 的控制信号，而不必单独部署探针，或作为探针的校准互补。

开放方向（尚未跑）

1. Decision 原生 DiffAdapt

用 /v1/decisions 替换或对照 MLP：choice∈{Easy,Normal,Hard}，可选 score 估长度、yes_no 控 think；低 label_mass 则升到 Normal。尽量复用 DiffAdapt Stage-1 标签。

2. 难度感知 serving

决策输出 → max_tokens、think 开关、投机激进程度、KV/优先级。评准确率、goodput、P90 TTFT、峰值 KV——对齐 JevServe 长度预测叙事与 DiffAdapt 的 token 节省（Li et al., 2025）。

3. 在线重决策

生成 k token 或熵尖峰后再问 continue / early-stop / 升级（优先 Easy→Normal）。对照早期退出 CoT（Yang et al., 2025）。

4. Bake-off

探针 vs chat /v1/decisions vs Jev，同难度标签，尤其 OOD（数学 → MMLU-Pro / GPQA）。

若成文一篇：Serving DiffAdapt via Decision APIs——自适应策略 + 准入控制，落在标准 decision 接口上。

注意事项

  • 勿将 label_mass / System One confidence 当作校准正确率（SGLang；TypeSafe）。
  • 解码中决策须贴合引擎时延预算；网关侧决策是今日易赢点（JevServe）。
  • DiffAdapt 数字与 JevServe SLO 数字均仅引自原文；本文无新测。
